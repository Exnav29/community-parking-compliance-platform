# CPCP Architecture (Phase 0 summary)

## Tenancy
`SaaS control plane -> Organization (one isolated Frappe site) -> Estate(s) -> Zone/Unit -> people, vehicles, visits, incidents`.
Each organization site has its own database, private files, cache namespace, backups and secrets
(e.g. the anonymous-intake signing key lives in that site's `site_config.json`). Frappe roles alone are **not** the
cross-customer boundary; the site is. Inside a site, estate/unit scope is enforced server-side.

## Layers
- `core/` pure Python domain rules (no Frappe import): `authz`, `visits`, `noticeclock`, `charges`, `allegations`,
  `auditchain`, `geo`, `flags`, `plates`, `phones`. 64+ unit tests.
- `permissions.py` adapts `core.authz` to Frappe: actor is derived only from server-side Role Assignments;
  `has_permission` and `permission_query_conditions` are registered for every CPCP DocType.
- `api/` whitelisted services: `session`, `registry`, `visitors`, `allegations`. Each calls `authorize()` first and
  returns minimal projections; denials are audited and leak no reason.
- `cpcp/doctype/` 24 DocTypes generated by `scripts/gen_doctypes.py`; append-only types inherit `AppendOnlyDocument`.
- `services/audit.py` hash-chained audit events + sensitive-access log.

## Key decisions (see docs/decisions)
- ADR-0001: Frappe v15 (current stable release line); revisit v16 once released as stable.
- ADR-0002: Capacitor + React for the shared mobile client; validated by Phase 0 device PoC (pending).
- ADR-0003: Site-per-organization tenancy.
- All stored datetimes are UTC (site system timezone forced to UTC); display uses estate timezone.

## Privacy boundaries
Residents: no registry/visitor-log access (hard invariant in `authz.decide`, tested). Anonymous intake: unauthenticated
endpoint, rotating community code, no session/IP/device stored in the record; label stays "Confidential" until
`anonymous_label_verified` is set after a logging review. Legal/enforcement flags default OFF and need an approval reference.
